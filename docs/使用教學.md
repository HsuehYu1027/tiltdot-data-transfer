# tiltDot 資料轉換工具 使用教學

## 一、安裝

1. 執行 `tiltdot-setup-x.x.x.exe`，一路按下一步即可。
   預設安裝位置是 `C:\Users\<你的帳號>\AppData\Local\Programs\tiltdot`。
2. 安裝完成後，桌面會出現「tiltDot 資料轉換工具」捷徑，點兩下即可啟動。

安裝檔已內含 Python 執行環境與 Chromium 瀏覽器，**不需要另外安裝 Python、
VS Code 或執行 `playwright install`**。

> 執行時會實際跳出一個 Chromium 視窗（程式正在自動操作網站），屬正常現象，
> **執行期間請勿手動關閉或操作該視窗**。

---

## 二、輸出位置與設定檔

### 輸出資料夾

程式預設把產出建在 **exe 所在的資料夾**底下：

```
<安裝資料夾>\初始檔案      ← 從網站下載的原始檔
<安裝資料夾>\修改過的      ← 程式處理後的 Excel 與報告
```

每次啟動時會先顯示目前的輸出位置，並讓你輸入新的路徑（直接按 Enter 就沿用）。
改過一次之後會被記住，下次不用再輸入。

若安裝位置沒有寫入權限（例如手動裝到 `C:\Program Files`），程式會自動改用
`我的文件\tiltdot`，並在畫面上告知。

### 設定檔 `tiltdot_config.json`

放在 exe 旁邊，第一次執行時自動產生。用記事本即可修改，存檔後下次執行生效：

| 欄位 | 說明 | 預設值 |
|---|---|---|
| `url` | 資料查詢網址 | WMS view_mqtt 頁面 |
| `output_root` | 輸出根目錄，留空代表 exe 所在資料夾 | `""` |
| `remove_outliers` | 是否自動剔除異常值 | `true` |
| `outlier_threshold` | 異常閾值（arcsec），超過即視為異常 | `10000` |
| `headless` | `true` 則不顯示瀏覽器視窗 | `false` |
| `default_wait_ms` | 網頁元素等待時間（毫秒） | `4000` |
| `download_timeout_ms` | 下載等待時間（毫秒） | `30000` |
| `date_col` / `time_col` | 原始檔中日期／時間的欄位編號，**1 代表第一欄(A)** | `2` / `3` |
| `date_order` | 日期順序：`auto` / `DMY` / `MDY` | `auto` |

## 三、執行流程

啟動後依畫面提示依序輸入：

1. **輸出資料夾**：直接 Enter 沿用目前位置。
2. **執行模式**：
   - `1` 資料轉換模式（transfer）— 預設，直接按 Enter 即可
   - `2` 補償驗證模式（test）— 額外產出補償後欄位與圖表
3. **儀器序號**：例如 `36901-36919`，或 `36901,36905,36910` 混用。
   起訖顛倒會自動對調，重複的序號會自動去除。
4. **軸數設定**：`XYZ` 或 `XY`（兩者都一定包含溫度 T）。
5. **欄位對應**：依原始資料格式輸入 X、Y、Z、T 各在第幾欄，
   可輸入數字（`5`）或 Excel 字母（`E`）。
6. **起訖日期與時間**：日期用 `YYYY-MM-DD`，時間 `HH:MM` 或 `HH:MM:SS` 皆可
   （`7:45` 會自動補成 `07:45:00`）。格式不對會當場要求重新輸入。

執行過程中，每個序號都會顯示「原始資料 N 筆，時間範圍內 M 筆」，
方便確認時間範圍是否設對。

## 四、檔案產出與格式

處理後的 Excel（放在「修改過的」）會有以下變動：

- 第一列插入資料種類標記：X、Y、Z 傾斜資料與環境溫度 T。
- 資料右側新增換算欄，單位為角秒（sec）。以 X 軸為例：
  `X(sec) = (x - x0) * 3600`，其中 `x0` 是**基準值**。
- 最後一欄 `ΔT` 為相對基準溫度的溫差。
- 圖表嵌在資料右側的空白區（不會蓋住資料）。

> **基準值怎麼取？** 取「第一筆 X／Y／Z／T 全都是有效數值」的那一列。
> 若第一列有缺值或被判定為異常，基準會自動往後移，圖表與 Excel 公式一律使用同一列，
> 兩邊不會對不起來。

---

## 五、圖表標示說明

圖表是 XYZ(sec) 與溫度 T 的疊圖，右下角文字方塊標示：

1. `T Peak`：溫度峰值。
2. 各軸 `Peak`：該軸在溫度變化下的最大偏移量（arcsec）。
3. `ΔT`：峰值發生當下的溫差。
4. `Error`：峰值除以溫差得到的偏差值，單位為角秒/°C。

---

## 六、異常值過濾機制

- **自動剔除**：換算後絕對值超過 `outlier_threshold`（預設 ±10000 arcsec）的資料點，
  會在 Excel 中把該列的原始值與換算值清空，圖表上該處斷開。
  可用設定檔的 `remove_outliers` 關閉。
- **檔名標示**：含異常資料的檔案，檔名前會加上 `[異常]_`。
- **過濾報告**：「修改過的」資料夾中會產生 `異常資料過濾報告.txt`，
  分三段記錄：
  1. 範圍內無資料或下載失敗的序號（含原因）
  2. 已下載但轉換失敗的序號（含原因）
  3. 各檔案的異常資料明細（發生時間、對應的 Excel 列號、數值）

## 七、回歸參數總表

所有序號處理完後，程式會統整**本次產出的檔案**（不會混入上次執行留下的舊檔），
產生 `Linear_Calibration_Parameters.xlsx`：

- 排除異常點後，以「單一最高峰值點與基準點連線」計算各軸的最極端偏差斜率。
- 表內含各感測器的基準溫度 `T_base` 與各軸補償係數 `cx`、`cy`、`cz`，
  可直接用於產品 SD 卡設定檔的溫漂補償。

若總表正被 Excel 開啟導致無法覆寫，程式會自動改存成帶時間戳的新檔，不會中斷。

---

## 八、補償驗證模式（TEST）

啟動時選擇 `2` 會在一般轉換的基礎上額外做溫漂補償：

- **係數計算**：以「最大峰值」與基準點的兩點連線法，算出各軸補償係數。
- **新增欄位**：Excel 右側增加「補償後X(sec)」「補償後Y(sec)」（XYZ 模式含 Z）。
- **補償公式**：`(原始讀數 - 基準值 + 補償係數 * ΔT) * 3600`。
- **補償後圖表**：在第一張圖下方再嵌入一張，曲線標示為 Comp X／Comp Y／Comp Z，
  右下角標示補償後的各軸峰值。

比對上下兩張圖，即可直觀確認補償係數是否有效壓下溫度造成的偏差。

## 附錄 A、用原始碼執行（開發者）

不使用安裝檔時：

```
python -m pip install -r requirements.txt
python -m playwright install chromium
python tiltdotdatatransfer.py
```

此模式下輸出資料夾預設建在 `.py` 所在的資料夾（不是上一層）。

## 附錄 B、常見問題排除

| 症狀 | 原因與處理 |
|---|---|
| 視窗一閃就關掉 | 已修正：程式結束或出錯都會停在「按 Enter 關閉視窗」。若仍發生，請改用桌面捷徑啟動並回報畫面訊息 |
| 「瀏覽器元件無法啟動，請重新安裝本程式」 | 內嵌的 Chromium 缺檔，多半是安裝過程被防毒軟體刪檔。請重新安裝，必要時先把安裝資料夾加入防毒白名單 |
| 「原輸出位置沒有寫入權限」 | 安裝到了受保護的目錄（如 Program Files）。程式已自動改用「我的文件\tiltdot」，也可在啟動時輸入其他路徑 |
| 每台序號都印出「無資料或逾時」 | 先確認網站可否手動下載該序號資料。程式**未包含任何登入流程**，若網站已改為需登入才能查詢，須另行處理 |
| 「原始資料 N 筆，時間範圍內 0 筆」 | 起訖時間設定與資料實際時間不符；或原始檔日期是 `MM/DD/YYYY` 但被判成 `DD/MM/YYYY`。後者請把設定檔的 `date_order` 改成 `"MDY"` |
| 畫面出現「無法自動判定日期順序」 | 原始檔日期的日與月都 ≤ 12（例如 `08/12/2026`）無從分辨。確認實際格式後在設定檔指定 `date_order` |
| 「欄位設定超出原始資料範圍」 | X/Y/Z/T 的欄位輸入錯誤，超過原始檔實際欄數。重新確認後再跑一次 |
| Excel 換算欄顯示 `#VALUE!` | 欄位對應指到了非數值欄位。重新確認原始檔中 X/Y/Z/T 的實際欄位 |
| 總表沒有包含某些檔案 | 總表只統計**本次執行**產出的檔案。要重算舊檔請重新執行該批序號 |
